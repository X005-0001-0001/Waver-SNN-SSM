# 对比实验数据看板（compare_dashboard）

替代原来的 `compare_plots.py` / `compare_watch.py` / `compare_plots/compare_viewer.html`。
**只读**训练日志，不写入任何 run 目录。原来的三个文件保持原样，没有被改动。

---

## 启动

双击 **`start_dashboard.bat`**（或命令行 `python server.py 8777`），浏览器会自动打开
<http://127.0.0.1:8777/>。关掉窗口即停止。

依赖：**只用 Python 标准库**，无需 pip 安装（参数量统计会用 torch，若不可用则该列显示 `—`）。

### 可移植性（可以直接复制到别处用）

**扫描根目录 = 看板目录的「上一级」**，所以把整个 `compare_dashboard/` 文件夹复制到任何位置，
它就会扫描**新位置的上一级**目录 —— 把 run 文件夹（含 `training_log.txt` 的子目录）和它放在同级即可。

```
某处/
├── compare_dashboard/     ← 复制到这里
├── 第4轮xxx/              ← 会被扫描到
├── 第4轮yyy/
└── ...
```

也可以显式指定扫描目录（第三个参数）：

```
python server.py 8777 1 "D:\别的地方\对照实验"
```

启动时的日志会打印 `看板目录` 与 `扫描根目录` 两行，一眼能确认对不对；
若一个 run 都没找到，会提示如何指定目录。
运行中产生的文件（`param_cache.json`）就放在看板目录内，**自包含**。

### 默认值（为「无法手动操作」的场合调好）

| 项 | 默认 |
|---|---|
| 对数 Y（主图） | **开** |
| 平滑 | **拉满 ≈2001 步** |
| 实时刷新间隔 | **2 秒** |
| 第二张图 | **验证 PPL（按 epoch）**（可一键切「差值」）|
| 基准 run | **验证 PPL 最优**的那个（切到差值模式时就是"其余相对最优"）|
| 选中范围 | **最近改动过日志的那个批次**（按 `第N轮` 前缀分组）|
| 横轴 | 记录序号 |

这几项都是为了让画面在**不点任何东西**的情况下就已经可读 —— 适合直播姬之类的场景。

**运行中的 run 会有明显的光效**（直播时一眼看出谁还在跑）：
曲线外加一层同色**呼吸式发光**（2.2s 脉冲）、线末端一个**跳动亮点 + 扩散光环**、
图例里该项前有一个**闪烁的绿点**。已停的 run 没有这些效果 —— 只影响观感，不影响数据。

启动参数：`python server.py [端口] [是否开浏览器 0/1] [扫描目录]`

## 与旧工具的区别

| | 旧（compare_plots / compare_watch） | 新看板 |
|---|---|---|
| 图的表现 | matplotlib 出 PNG，前端只轮播图片 | SVG 直接绘制，**可交互** |
| 交互 | 无（每次重载整张图） | 悬停十字线+数值、滚轮缩放、拖拽平移、双击复位、点图例开关曲线 |
| 横轴 | 日志行序号 | 记录序号 / **真实 step** / **epoch** 三选一，并画出 epoch 分界线 |
| 刷新 | 每 3s 重新下载 PNG；20s 全量重解析日志 | **SSE 推送 + 增量解析**（只读新增字节）+ **数据版本号驱动的取数**，有新数据才请求 |
| 验证曲线 | 无 | 「验证 PPL / 验证 Loss」独立曲线 + **Epoch 明细表** |
| 运行元信息 | 无 | 参数量 / H / L / S / SEQ / Loop / 耦合 / dk / 最优验证 PPL@epoch / 最后 loss / 速度 / ETA |
| 平滑 | 固定 EMA 0.999 | 滑杆实时调，**指数刻度**（窗口 1 ~ 2001 步），默认 ≈100 步 |
| 选 run | 每次启动手动输序号 | 侧栏勾选 + **关键字筛选** + 全选/清空/反选/仅前 3 优/按最优排序 |
| 差值图 | 只有 loss | 任意指标都可切「差值（相对选定基准）」 |
| 主题 | 仅深色 | 深色 / 浅色切换（记忆） |

## 界面说明

**顶栏**：实时开关 / 刷新间隔 / 平滑滑杆 / 对数Y / 差值 / 基准 run / 横轴 / 立即刷新 / 主题。
右上角显示 `N runs · M 条记录 · 时间`。

**主图**：默认开**对数 Y**（能压住早期的大幅下降，露出尾部分歧）+ **平滑 ≈2001 步**。
顶栏的「差值」按钮可把主图也切成差值模式。

**平滑滑杆**：刻度是**指数**的，滑杆位置线性映射到"等效平均窗口"（1 ~ 2001 步），
所以整条行程都有可见效果 —— 最左=不平滑，中段≈20~100 步，最右≈2000 步（很平滑）。
标签直接显示窗口步数（如 `≈2001步`），图的标题也会写出来。拖动时**防抖 130ms**，只在停顿后发一次请求。
EMA 的起点用前 k 个点的均值初始化，所以重平滑时**首段不会被第一个噪声样本拖住**。

**第二张图（验证 / 差值）**：默认是**验证 PPL（按 epoch）**。
标题右侧两个小按钮可切到「差值」—— 各 run 减去基准（在基准曲线上插值对齐），并画 y=0 虚线。

> 为什么值得留着差值模式：近似曲线在原图上必然重叠（实测：7 个 run 末段 loss 都在 2.0~2.3，
> 而主图 y 轴要跨 2.6~9.5，**末端只占轴向约 7%**，加对数也救不了）。
> 差值图把它们拉到同一水平后放大（实测范围 [−0.17, +0.26]，各 run 间距约 0.05 ≈ 轴向 20%），
> 是唯一真正能把近似曲线分开的看法。

**左栏**：run 列表。每个 run 显示颜色、状态（运行中/已停，按日志 mtime 判定）、
验证 PPL（最优标 ★）、记录数、参数量、实时记录速度。
上方按钮：全选 / 全清 / 反选 / 仅前3优 / 按最优排序；下面是关键字筛选框（空格分隔多个关键字）。

**指标页签**：Loss / PPL / LR / Activity / Memory(MB) / 验证PPL(epoch) / 验证Loss(epoch)。

**主图**：悬停看各条曲线的值；滚轮缩放、拖拽平移、双击复位；点图例文字可隐藏/显示某条曲线。

**第二张图**：固定展示验证维度（主图已是验证指标时自动换成另一个），方便和训练曲线对照。

**运行对比表**：所有元信息 + 最优验证 PPL（最优者蓝色高亮）。
**Epoch 明细表**：每个 run 的 train loss（该 epoch 均值）/ val loss / val PPL 并排。

## 数据来源与口径

* 每步曲线：日志里 `Epoch e/E Step s Loss: … PPL: … Activity: … LR: … … Memory: …` 行
* 验证曲线：日志里 `Epoch e 验证 Loss: … PPL: …` 行；
  同时解析 `best_epoch{e}_ppl{X}.pt` 文件名，两路互为校验（实测一致）
* 架构/训练配置：从 run 目录下的 `*elite.py` 或 `transformer.py` 提取（`HIDDEN_SIZE` / `NUM_LAYERS` /
  `STATE_DIM` / `MAX_SEQ_LEN` / `SUMMARY_TYPE` / `USE_LOOP` / `LOOP_CONFIG` / `DISABLE_COUPLING` /
  `SUMMARY_ATTN_DK` 等 40 余项）
* 参数量：**优先读训练日志里菜单 6 打印的"总参数"**（`sum(p.numel() for p in model.parameters())`，精确，与菜单一致）；
  日志里没有时，退回"加载 `best_epoch*.pt` 的 `state_dict` 并按张量**去重**后求和"（近似，表格里标 `~`）。
  **为什么必须去重**：`TIE_EMBEDDING_OUTPUT=True` 时 `output_fc.weight` 与 `embedding.weight` 共享同一块存储，
  `state_dict` 里是两个键指向同一个张量；按"键"求和会把 embedding 数两遍
  （实测：transformer 虚高 2,576,000、waver 虚高 1,792,000 —— 正是你看到的 9.0M/10.0M vs 7.2M/7.5M）。
  近似值还可能含极少量 buffer（如 `attn.rope.inv_freq`，3×23=69 个元素）。结果缓存到 `param_cache.json`
* 速度 / ETA：仅在日志正在增长时有意义；平均方式为近 2 分钟的记录增量

## HTTP API（可直接用于脚本/Notebook）

| 端点 | 说明 |
|---|---|
| `GET /api/meta` | 数据根目录、版本、扫描时间、run 数 |
| `GET /api/runs` | 全部 run 的快照（含配置、参数量、val 序列、速度、ETA） |
| `GET /api/series?runs=a,b&metric=loss&smooth=0.99&xaxis=step&points=1400` | 曲线（服务端 EMA 平滑 + 最小/最大桶降采样 + epoch 分界） |
| `GET /api/epochs?runs=a,b` | 每 epoch 的 train/val 明细 |
| `GET /api/run?name=X&tail=60` | 单个 run 的配置 + 末尾 N 条原始记录 |
| `GET /api/events` | SSE 事件流（版本号 + 各 run 日志大小） |

`metric` 取值：`loss` / `ppl` / `lr` / `act` / `rss` / `val_ppl` / `val_loss`；
`xaxis` 取值：`seq`（记录序号）/ `step` / `epoch`。

## 实现要点

* **增量解析**：每个 run 记录已消费的字节偏移与半行残留，只解析新增部分；
  日志被截断时自动重置。实测 24 个 run、~98 万条记录，首轮全量 **8 秒**，之后每 2 秒只读增量。
* **服务端降采样**：`min/max 桶` 保留包络，默认 1400 点/条（约 2800 个绘制点），避免前端画 10 万点。
* **参数缓存**：避免每次启动都加载 30MB checkpoint。
* 视图窗口、主题、选中项存在前端内存 / `localStorage`（主题）。

### ⚠️ 改这个文件前必读：实时更新靠"缓存键带版本号"

主图的取数在 `refreshSeries()` 里，缓存键是：

```js
const key = [sel.join(","), S.metric, S.smooth, S.xaxis, S.version].join("|");
```

**`S.version` 千万不能去掉。** 它来自 `/api/runs`（服务端只在日志真的追加了字节时才递增）。
去掉它，首次取完数据后每次 tick 的键都不变 → 只走 `redraw()` 重绘旧数据 →
**主图会永久冻结在第一次的数据上，看起来完全不实时**（这个坑真的踩过）。
带上版本号后：有新数据才请求，无新数据也不浪费请求。

### 各元素的实时性

| 元素 | 更新时机 |
|---|---|
| 主图（Loss / PPL / LR / Activity / Memory） | **每次有新记录**（秒级） |
| 第二张图 · 差值模式 | 同上（用的是主图数据） |
| 第二张图 · 验证模式 | **每个 epoch** 一次（验证指标本身就是按 epoch 算的） |
| 页签「验证PPL(epoch)」「验证Loss(epoch)」 | **每个 epoch** 一次（x 轴是 epoch 号，不是 step） |
| 运行对比表 / 侧栏 / 状态栏 | 每次有新记录 |
| Epoch 明细表 | 每个 epoch |

> 「验证」相关的东西**天然是 epoch 级的** —— 一个 epoch 可能好几个小时，别误以为卡住了。
