# 对比实验数据看板 · 直播版（live_dashboard）

给**直播**用的一套。后端与 `compare_dashboard` 是同一套（API 完全一致，默认端口 **8778** 避免冲突），
前端为直播重写：**画面永不静止 + 一眼可读**。

---

## 启动

双击 **`start_live.bat`** → 浏览器自动打开 <http://127.0.0.1:8778/>

和旧看板（8777）**可以同时开**，互不干扰。依赖：只用 Python 标准库。

---

## 针对你的三个问题，分别做了什么

### ① B 站判挂机 → 让画面持续有运动

平台的挂机检测看的是「**画面变化量**」。而训练曲线本身几小时才动一点点 —— 这是被判挂机的根因。
所以补了 **6 层与数据无关的持续动画**：

| 元素 | 变化频率 |
|---|---|
| 顶栏大时钟（近似秒表） | **每秒**跳变 |
| 当前 epoch 进度条 + 扫过的流光 | 每 2 秒增长 / 流光连续 |
| 底部滚动字幕 | 连续横向滚动 |
| 运行中曲线的呼吸光晕 | 2.4 秒一个明暗周期 |
| 曲线末端的跳动亮点 + 扩散光环 | 1.6 / 2.4 秒 |
| 自动聚焦轮换（高亮换到下一条曲线） | 每 15 秒 |

> 右下角放摄像头解决不了问题：平台看的是**画面像素有没有在变**，
> 而不是「画面里有没有人」。静态的人像和静态的图表一样会被判挂机。

### ② 画质不高 → 全部按 1080p 直播重新定尺寸

| | 旧版 | 直播版 |
|---|---|---|
| 关键数字 | 12 px | **40 px** |
| 坐标轴刻度 | 10 px | **17 px** |
| 曲线粗细 | 1.5 px | **3.2 px**（运行中 4 px + 光晕）|
| 网格线 | 密集 | 淡化、减少 |

配色换成高对比深色，远处也看得清。

### ③ 一堆细线糊在一起 → 从源头减量

**视图范围按钮**在三种模式间循环（顶栏，默认第一种）：

| 模式 | 画什么 |
|---|---|
| **全部运行**（默认） | **所有正在训练的**，不限条数。新启动的训练会自动加入、跑完的自动移出 —— 直播时不用动任何按钮 |
| 精选 6 条 | 成绩（最优验证 PPL）最好的 6 个，适合回看已完成实验的对比 |
| 全部 | 所有有数据的实验 |

默认用"全部运行"而不是"精选"，是因为正在跑的这批训练长度接近，曲线能铺满整张图；
若把已跑完的实验混进来（比如 100k 那个跑到 89500 步，而在跑的才 8000 步），
在跑的会被压进左边一小块挤成一团 —— 这正是第一版的问题。

另外还有：
- **自动聚焦**：每 15 秒把高亮点切到另一条曲线，其余压到 24% 透明度 —— 同一时刻只需要看一条
- 曲线超过 6 条时，仍然靠聚焦来避免"一团线"

## 界面

```
┌ LIVE  时钟 已运行 │ …… │ 自动聚焦  指标  精选6条 ┐
├ 进度条（当前 epoch 完成度，带流光）                ┤
├ 六张大数字卡片：轮次 / 当前损失 / 当前困惑度 /      ┤
│              最优验证PPL / 训练速度 / 预计剩余      ┤
├──────────────────────────────┬────────────────────┤
│  主图（粗曲线 · epoch 分界 ·   │  排行榜             │
│        聚焦高亮 · 运行中光效）  │  （按最优 PPL 排序） │
├──────────────────────────────┴────────────────────┤
│ ◀ 滚动字幕：实时播报每个运行中任务的状态 ▶          │
└───────────────────────────────────────────────────┘
```

交互仍然保留：悬停看数值、滚轮缩放、双击复位、点图例可手动聚焦某条。

## 默认值（无人操作也好看）

| 项 | 默认 |
|---|---|
| 指标 | 训练损失 |
| 平滑 | 400 步 |
| 对数 Y | 开 |
| **横轴** | **记录序号**（不是 step —— 见下方说明）|
| 画哪些 run | **全部正在运行的**（不限条数；新启动的训练会自动加进来）|
| 视图范围按钮 | 循环切换：**全部运行**（默认）→ 精选 6 条 → 全部 |
| 自动聚焦 | 开，15 秒一轮 |
| 刷新 | SSE 推送 + 4 秒兜底轮询 |

另外，卡片上的「当前损失」取的是**平滑序列**的尾部均值，不是最后一个 step 的原始值
（日志每个 step 一条、batch=1，单步 loss 噪声极大 —— 实测见过某一 run 的末步 loss = 0.10）。
目录名一律**截头留尾**显示（`…seed42coup0.368`），因为公共前缀太长，截头会全部长得一样。

### ⚠️ 横轴为什么必须是「记录序号」而不是「step」

日志里的 `step` **在每个 epoch 结束后会重置回 1**。若横轴用 step，10 个 epoch 的数据会在图上
**反复横跳、彼此叠在一起**：

| 横轴 | 基线那条曲线 | 单调？ | 回跳次数 |
|---|---|---|---|
| step | x ∈ [1, 8897] | **否** | **9 次**（正好是 10 个 epoch 的 9 个衔接处）|
| 记录序号 | x ∈ [1, 88979] | 是 ✓ | 0 |

同时服务端返回的 epoch 分界标记是按「记录序号」算的，配 step 轴必然错位。

**记录序号**是单调递增的（1,2,3,…），曲线从左到右一路推进，epoch 分界线也落在正确位置。
（旧版的横轴默认值本来就是记录序号，这一点没在旧 README 里写下来 —— 改前端时别把它改掉。）

## 可移植（和旧版一样）

**扫描根目录 = 看板目录的上一级**，所以把整个 `live_dashboard/` 复制到任何位置，
它就去扫**新位置的上一级**：

```
某处/
├── live_dashboard/     ← 复制到这里
├── 第4轮xxx/            ← 会被扫描到（子目录里有 training_log.txt 即可）
├── 第4轮yyy/
└── ...
```

也可以显式指定扫描目录：

```
python server.py 8778 1 "D:\别的地方\对照实验"
```

## 与旧看板的关系

| | `compare_dashboard`（旧） | `live_dashboard`（新） |
|---|---|---|
| 端口 | 8777 | **8778** |
| 定位 | 分析用：全功能、可交互 | 直播用：自动、大字号、防挂机 |
| 曲线数量 | 想选几条选几条 | **默认 ≤ 6 条** |
| 交互 | 全套（含拖拽平移） | 保留悬停/缩放/复位，但**默认不需要动** |
| 表格 | 运行对比表 + Epoch 明细 | 换成**排行榜**（直播看不了那么多字）|
| 后端 | — | **同一套**（API 一致，可互换使用）|

**旧版完全没动过。** 两个看板可以同时开着。

## ⚠️ 改前端前必读（沿用旧版的教训）

主图取数的缓存键是：

```js
const key = [sel.join(","), S.metric, S.smooth, S.version].join("|");
```

**`S.version` 千万不能去掉。** 它来自 `/api/runs`，服务端只在日志真的追加了字节时才递增。
去掉它 → 首次取完数据后键不再变化 → 只重绘旧数据 → **主图永久冻结，看起来完全不实时**（这个坑真踩过）。

另外：`S.view` 里保存缩放窗口，`S.focus` 保存当前聚焦的 run，都只存在于前端内存。
