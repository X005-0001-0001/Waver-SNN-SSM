# v6 低精度方案 + 训练侧加速 验证报告

平台：Windows 11 / RTX 5080 16GB (sm_120) / Python 3.13 / torch + bitsandbytes
基线：`对照测试\v6\312006elite.py`（H=256, L=12, T=4096, STATE_DIM=4, K=2, MoE=off）
所有实验在 `v6*` 副本目录进行，不改动 `v6` 原始基线。种子统一 42，LR=1e-3，WD=0.01。

## 一、8-bit AdamW（bitsandbytes `AdamW8bit`）—— ✅ 可用，不爆炸

**问题**：这套复值 SSM 上，Adafactor 会把 `nu_max` 漂到 36、`An` 漂到 709；Lion 会把权重范数顶到 15–36×。8-bit 优化器会不会同样爆炸？

**实验**：`v6测试8bit`(AdamW8bit) vs `v6测试8bit_ctrl`(AdamW)，其余配置逐字节一致，各跑 400 步。

| 指标 | 末步(399) 基线 | AdamW8bit | 相对偏差 |
|---|---|---|---|
| loss | 7.6335 | 7.6430 | 1.24e-3 |
| Bn | 2.609 | 2.605 | 1.28e-3 |
| Sn | 18.447 | 18.439 | 4.70e-4 |
| Dn | 1.841 | 1.844 | 1.63e-3 |
| Mn | 2.166 | 2.166 | 3.85e-5 |
| An | 20.874 | 20.884 | 4.91e-4 |
| nu_max | 0.994 | 0.992 | 1.84e-3 |
| In | 18.465 | 18.465 | 1.35e-5 |

- **全程最大相对偏差**：所有 MON 指标 < 3.4e-3（Bn 2.27e-3 / Sn 5.74e-4 / Dn 3.36e-3 / Mn 3.46e-4 / An 5.87e-4 / nu_max 2.18e-3 / In 1.44e-4）。
- **首末步比值**：全部 `x1.00`，400 步无任何单调漂移。
- 偏差量级 = bf16 量化噪声量级，与「爆炸」相差 3–4 个数量级。

**显存**（`v6测试8bit\probe_opt_memory.py`，同模型 24.3M 参数）：

| 优化器 | 稳态分配 | 峰值 |
|---|---|---|
| AdamW | 421.7 MB | 421.7 MB |
| AdamW8bit | 271.1 MB | 271.1 MB |

→ **省 150.5 MB（35.7%）**，与「动量状态 fp32→8bit」的理论值（~145MB）吻合。

**结论**：✅ 推荐启用。与 Adafactor/Lion 的失效模式本质不同——8bit 只是把一阶/二阶动量做了分块线性量化，更新方向与幅度仍由梯度决定；Adafactor 的失效源于其非对角预条件与相对步长，Lion 源于 sign 更新对梯度幅度不敏感。8bit 不改变更新规则，只降状态精度。

## 二、MoE 专家量化 —— ✅ 三种精度全部可用

`MOE_ENABLED=True`（每层 SSM 后接 SwiGLU MoE，8 专家 top-2，`MOE_EXPERT_WNORM=True`）。

### 2.1 fp8_e4m3（训练期 STE 量化）
`v6测试fp8`(fp8_e4m3) vs `v6测试moe_ctrl`(None)，各跑 300 步。

- 全程最大相对偏差：Bn 3.25e-3 / Sn 1.23e-3 / Dn 3.13e-3 / Mn 2.31e-4 / An 5.78e-4 / nu_max 3.51e-3 / In 2.62e-4。
- 首末步比值全部 `x0.99–1.00`。
- MoE 专家权重范数 `[MOE Lx] Rr / Wg / Wu / Wd` 两者逐层吻合（fp8：Wg 0.97–1.01；对照：Wg 0.985–1.007）。
- **结论**：✅ 训练期 E4M3 权重量化稳定，STE 梯度回传正常，无范数爆炸。

### 2.2 nvfp4（推理 4-bit，逐块 scale）
`v6测试nvfp4\probe_quant_all.py`（同 seed 构建 None / bf16 / nvfp4 三模型对比）：

| 量化 | 参数量 | 稳态分配 | 峰值 | 省显存 | logits max_abs | rel_norm | 生成 |
|---|---|---|---|---|---|---|---|
| None | 100.06M | 401.9 MB | — | — | — | — | ✅ |
| bf16 | 24.56M* | 341.9 MB | 425.1 MB | 14.9% | 0.0000 | 0.0000 | ✅ |
| nvfp4 | 24.56M* | 218.6 MB | 301.6 MB | **45.6%** | 0.0007 | **2e-4** | ✅ |

\* 专家权重打包为 buffer，不再计入 `parameters()`，故参数量骤降；这是统计口径，非真实容量变化。

- **结论**：✅ nvfp4 推理可用，省显存 45.6%，logits 相对误差仅 2e-4，生成正常。bf16 打包几乎无损（rel 0.0000），但只省 14.9%。
- 注意：`nvfp4` / `bf16` 打包路径会**强制关闭专家 offload**（代码 `if expert_quant in ('nvfp4','bf16'): offload=False`），因为权重要常驻打包态。

## 三、训练侧加速 —— 结论：收益**比预想大**（3.4×）

### 3.1 诊断：训练步严重 launch-bound
`v6测试8bit_ctrl\probe_train_graph.py`（H=256 L=12 T=4096 B=1 bf16）：

```
grad_checkpoint=True   单步 1745.6 ms   峰值显存 1478.9 MB
grad_checkpoint=False  单步 1106.0 ms   峰值显存 9367.3 MB
=== kernel 剖析（每步）===
墙钟 1745 ms | CUDA 忙 680 ms | 启动次数 ~104,946 | 空闲占比 ~61%
```

- 每步 **~10.5 万次 kernel 启动**，CUDA 实际忙仅 680ms → **~61% 时间耗在启动/调度**。这是 CUDA Graph 的教科书场景。

### 3.2 梯度检查点：直接关掉，快 1.58×
- gc=False 1106ms vs gc=True 1745ms → **快 1.58×**，峰值显存 1.5GB→9.4GB。
- **16GB 完全放得下**，所以「激活 offload」这条其实**不需要**——直接关检查点即可拿到速度，且不引入 PCIe 搬运开销。激活 offload 只会更慢。

### 3.3 训练步 CUDA Graph：抓 fwd+bwd，2.4–2.6×
`v6测试8bit_ctrl\probe_train_graph_capture.py`：

```
gc=False  eager(fwd+bwd)=1245.7 ms  graph=511.1 ms  加速=2.44x
gc=True   eager(fwd+bwd)=1866.8 ms  graph=707.6 ms  加速=2.64x
```

**两个阻塞点（已定位并验证）**：
1. `WaveSNN.forward` 内 `avg_activity = (...).item()`（约 2627 行）→ `.item()` 触发 GPU→CPU 拷贝，使抓图 `cudaErrorStreamCaptureInvalidated`。**改为 `.detach()` 返回张量后，fwd 与 fwd+bwd 抓图立即成功**（已实测）。日志打印 `.item()` 挪到抓图区外即可。
2. `optimizer.step()` 入图需 `AdamW(capturable=True)`；bnb `AdamW8bit` 不支持 → **把 opt.step 留在图外**（fwd+bwd 才是启动开销大头，仍拿到绝大部分收益）。

**组合最优**：`gc=False` + 训练图 = **511 ms/step**，对比原始 `gc=True` eager 的 1745 ms → **整体 3.4×**。

> 注：MoE 开启时 `_dispatch_experts` 里有 `bool(hit.any())` / `nonzero()` 等 host 同步，动态路由会破坏抓图；训练图目前只适用于 **MoE 关闭的静态形状路径**。MoE 路径要入图需先把路由改为定长 padding 的静态 gather。

## 四、总表与建议

| 方案 | 可用性 | 显存/速度收益 | 稳定性 | 建议 |
|---|---|---|---|---|
| **AdamW8bit** | ✅ | 省 35.7% 优化器显存 | 偏差<3.4e-3，无漂移 | **启用**（`OPTIMIZER_TYPE='adamw8bit'`） |
| **fp8_e4m3 专家量化（训练）** | ✅ | 权重带宽↓ | 偏差<3.5e-3 | 可按需启用 |
| **nvfp4 专家量化（推理）** | ✅ | 省 45.6% 模型显存 | logits rel 2e-4 | **推理启用** |
| **bf16 专家打包（推理）** | ✅ | 省 14.9% | 近乎无损 | 备选 |
| **关梯度检查点** | ✅ | **1.58× 提速**，显存 1.5→9.4GB | 无影响 | **启用**（16GB 够） |
| **训练步 CUDA Graph** | ⚠️ 需小改造 | **2.4–2.6× 提速** | 数学逐位一致 | 去掉 forward 内 `.item()` 后启用 |
| **激活 offload** | ❌ 不需要 | 负收益 | — | 不启用 |

**推荐组合**：`AdamW8bit` + 关梯度检查点 + 训练步 CUDA Graph（去 forward 内 `.item()`）→ 显存省 ~36%，训练速度 **约 3.4×**，且所有 MON 权重范数稳定。
